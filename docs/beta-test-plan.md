# 소수 직원 베타 테스트 계획

## 시작 조건

- 베타 참여자와 공개할 업무용·휴대전화 번호 범위를 합의하고, 가능하면 원본 파일에 `active`와 `mobile_visible` 열로 기록합니다.
- 사무실 전화가 외부로 발신할 때 직원별 직통번호가 수신 단말에 표시되는지 먼저 확인합니다.
- 각 플랫폼에서 최소 2명을 선정해 서로 통화할 수 있게 합니다.
- 실제 번호가 포함된 CSV는 Git, 메신저, 문제 보고서에 첨부하지 않습니다.

## 기능 확인

1. 정상 CSV import가 성공하고 공개 대상으로 표시한 사무실·휴대전화 번호가 각각 E.164 항목으로 변환되는지 확인합니다.
2. 잘못된 번호, 필수값 누락, 서로 다른 직원의 중복 번호가 import를 중단시키는지 확인합니다.
3. `active` 열이 없으면 `--assume-active` 없이는 거부되고, 공개 여부 열이 없는 휴대전화는 `--include-mobile` 없이는 제외되는지 확인합니다.
4. token이 없거나 틀리면 API가 명부를 반환하지 않는지 확인합니다.
5. 앱 동기화 후 네트워크를 끈 상태에서도 알려진 번호가 표시되는지 확인합니다.
6. 알 수 없는 번호와 발신번호 비공개 통화가 직원으로 잘못 표시되지 않는지 확인합니다.
7. CSV의 조직명을 변경해 재import한 뒤 앱을 동기화하면 새 레이블이 표시되는지 확인합니다.
8. `active=false`로 변경한 직원이 다음 snapshot과 발신자 ID 목록에서 사라지는지 확인합니다.

## iOS 추가 확인

- 설정에서 Call Directory extension을 활성화한 뒤 상태가 앱에 반영되는지 확인합니다.
- 사용자 연락처에 이미 저장된 번호와 저장되지 않은 번호를 따로 테스트합니다.
- 앱을 종료하고 단말을 잠근 상태에서 레이블 노출을 확인합니다.

## Android 추가 확인

- 앱을 기본 발신자 ID·스크리닝 앱으로 선택한 뒤 역할 상태가 반영되는지 확인합니다.
- 수신음이 늦어지지 않고 발신자 ID UI가 잠금화면에서도 확인 가능한지 Pixel과 Samsung 기기에서 각각 검증합니다.
- 후스콜 등 다른 screening 앱을 선택했을 때 이 앱이 비활성화되는지 확인합니다.
- 마지막 성공 확인 시각이 7일을 넘긴 시험 snapshot에서는 직원 정보가 표시되지 않는지 확인합니다.

## 베타 종료

- 각 단말에서 앱의 로컬 명부/토큰 삭제 기능을 먼저 실행한 뒤 서버 token을 폐기합니다. token 폐기만으로 iOS에 이미 적재된 Call Directory 항목이 지워지지는 않습니다.
- iOS Call Directory 목록과 Android 로컬 명부가 제거되었는지 확인합니다.
- 제거를 확인한 다음 앱을 삭제합니다.
- 시험 참여자의 피드백에는 실제 전화번호 대신 재현 절차와 앱 버전만 남깁니다.
